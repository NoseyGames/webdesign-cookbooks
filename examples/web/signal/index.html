Research isn’t finished when it’s filed away. A simple structure makes it easier to return, connect, and act.

  1. 01

    Keep the raw material.

    Capture the note and its source together. Separate what happened from what you think it means.

  2. 02

    Find a useful connection.

    Group evidence around a question. Let disagreement remain visible; it often shows you what to investigate next.

  3. 03

    Leave a clear next step.

Start with a tiny, portable data model. These equivalent examples select the open research notes and keep only what a follow-up needs.

Runs locally in Python 3 or a JavaScript console. No account, package, API key, or network request. This page displays code; it never executes it.

Python follow_up.py

import json

notes = [
    {"id": "R-01", "title": "Keep the source", "status": "open"},
    {"id": "R-02", "title": "Clarify the handoff", "status": "open"},
    {"id": "R-03", "title": "Archive the recap", "status": "closed"},
]

# A pure transformation: input stays unchanged.
follow_up = [
    {"id": note["id"], "title": note["title"]}
    for note in notes
    if note["status"] == "open"
]

print(json.dumps(follow_up, indent=2))

JavaScript follow-up.js

const notes = [
  { id: "R-01", title: "Keep the source", status: "open" },
  { id: "R-02", title: "Clarify the handoff", status: "open" },
  { id: "R-03", title: "Archive the recap", status: "closed" },
];

// A pure transformation: input stays unchanged.
const followUp = notes
  .filter((note) => note.status === "open")
  .map(({ id, title }) => ({ id, title }));

console.log(JSON.stringify(followUp, null, 2));
EXPECTED RESULT

R-01 Keep the source
R-02 Clarify the handoff

Sample data assumes every note has a string id, title, and status. Validate those fields before adapting this to external input.
